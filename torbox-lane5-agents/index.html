    What each agent ACTUALLY did¶

    1. Copilot CLI — ✅ RAN, full review (copilot.txt)¶

    Reinstalled: npm i -g @github/copilot → GitHub Copilot CLI 1.0.100 at /usr/bin/copilot. Ran non-interactively with COPILOT_GITHUB_TOKEN sourced from ~/.bashrc (value never logged). Findings: - Root cause (likely): tb_reqdl.py sends the authd surrogate to TorBox as if it were the API key — lines 15–17 extract entry["surrogate"] and insert it into ?token=, with no Authorization header and no credential exchange. A surrogate is a broker-specific substitute, not a TorBox key; with bearer_header registration, manually moving it into token is the bug. Fresh keys failing doesn't rule this out — the request still wouldn't contain the fresh key. - Ranked the other hypotheses low: URL-encoding is correct (quote(..., safe='')), path/order fine, redirect refusal would traceback not BAD_TOKEN, UA already set (Cloudflare 1010 ≠ BAD_TOKEN), plan cap would not be an auth error. - New bug found: torbox_add_magnet.py imports add_surrogate_to_request but calls url_with_surrogate_query_param(...), which is not imported or defined → NameError before any request. (Verified by reading the file in this lane.) - Diagnostic sequence: baseline via tb_mylist.py → retry requestdl through the broker's supported query_param placement → capture status/body/redirect with token redacted → only then check plan/caps. Do NOT regenerate the key as a diagnostic. - Caveat it stated itself: zip_extract.py access was denied in its sandbox, so it made no finding on that file; diagnosis is "strong, not proof" without the dynamic_credentials helper source.

    2. Codex — ⚠️ direct lane 401; ✅ full review via Kilo gateway (codex.txt, codex-kilo.txt)¶

    • Direct OpenAI lane: still broken. Exact error (codex.txt): failed to connect to websocket: HTTP error: 401 Unauthorized, url: wss://api.openai.com/v1/responses and unexpected status 401 Unauthorized: Missing bearer or basic authentication in header. Retried 5× then fell back; run was cut at timeout with the 401 already definitive.
    • Via Kilo Code free gateway (codex -p kilo-code exec, model openrouter/free, provider kilo-code): worked (sanity test CODEX_KILO_OK, then full review, 135,195 tokens). It read the actual dynamic_credentials module, so its diagnosis is the most specific:
    • Root cause confirmed by code: surrogate substitution only happens for the registered placement. custom.torbox is bearer_header; Sentinel/authd substitutes hsurr:... only in Authorization: Bearer. tb_reqdl.py:17-18 puts the literal surrogate in ?token= → TorBox sees the surrogate → BAD_TOKEN.
    • More bugs: tb_mylist.py:13, tb_export.py:12, torbox_add_magnet.py:34 all call url_with_surrogate_query_param on a bearer_header credential → predicted DynamicCredentialError: credential is not query_param at runtime (i.e. the "working" helpers would crash before sending, unless the credential was re-registered).
    • Fix A (preferred if requestdl accepts Bearer): use add_surrogate_to_request, drop &token=. Fix B (if ?token= truly required): register a second entry with {"query_param": "token"} placement and use url_with_surrogate_query_param everywhere.
    • Diagnostic sequence with expected outcomes for each step (placement print → tb_mylist crash test → Bearer-surrogate requestdl test).

    Consensus: Copilot and Codex/Kilo independently converged on the same root cause (surrogate in ?token= never substituted for a bearer_header credential). That also explains the "every fresh key dies as BAD_TOKEN" saga: the failing requests never contained any real key.
