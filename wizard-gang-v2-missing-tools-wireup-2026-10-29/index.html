    1. BasicPBC (Paint Bucket Colorization, CVPR 2024)¶

    • Upstream: https://github.com/ykdai/BasicPBC (official implementation, arXiv 2403.18342)
    • Install: git clone --depth 1 → ~/workspace/tools/basicpbc/ (was: directory gone entirely)
    • Pipeline role: colorize hand-drawn line frames by paint-bucket inclusion matching — feed it one colored keyframe (gt) + line frames, it colors the sequence. This is the "color the inbetweens from the key" stage of the cartoon factory.
    • VERDICT: WIRED+PROVEN — venv complete (torch 2.2.2+cpu + all deps import-verified; pin set in constraints.txt — without it timm drags in PyPI's CUDA torch; torch_scatter/matplotlib are imported by the code but missing from its requirements.txt). Both release checkpoints byte-exact: ckpt/basicpbc.pth 105,523,141 B, ckpt/basicpbc_light.pth 50,350,481 B. The seg stage's CLIP-convnext weights (1.41 GB, downloaded by open_clip at first use) are pre-staged in the local HF cache, the .bin blob SHA-256- verified byte-identical to upstream; run with HF_HUB_OFFLINE=1 so open_clip's safetensors-first lookup falls back to the cached .bin. CPU-portability patches (documented in tools/basicpbc/WIRING.md): map_location="cpu" on three bare torch.loads + conditional .cuda() at inference_line_frames.py:164 and basicsr/models/pbc_model.py:208 — the authors assume CUDA; GPU behavior unchanged. Proof: bundled laughing_girl frames (cv2-resized to 512² — PIL's RGBA resize destroys these frames) colorized end-to-end, 100% in 126 s/it: dataset/test/proof6/proof6/0001.png + color dict assigning the target frame's segments colors from the keyframe's own palette ([151,136,221], [86,16,35]); segmentation separately proven at native 1600² (117 segments, dataset/test/laughing_girl/seg/). Floors learned: <512² collapses segmentation to <2 keypoints (KeyError: 'match_scores'); the one-process native-res run OOMs on this shared 8 GB VM (CLIP ~2 GB + neighbors) — the two-stage --skip_seg split is the low-memory route. Full detail: tools/basicpbc/WIRING.md.

    2. FlashXFLParser (XFL/.fla rig-structure parser)¶

    • Upstream: https://github.com/jackisgames/FlashXFLParser (Unity C# project)
    • Install: git clone --depth 1 → ~/workspace/tools/FlashXFLParser/ (was: directory gone)
    • What the code actually is (read in full): the parser core is Assets/XFLParser/display/Symbol.cs — a pure-.NET XmlSerializer data model of an XFL library symbol (DOMSymbolItem → DOMTimeline → DOMLayer → DOMFrame → symbol/bitmap instances with matrices). editor/XFLLibraryEditor.cs is the import loop (deserialize every LIBRARY/*.xml into Symbol). Only Bitmap.cs/XFLLibrary.cs touch UnityEngine (Texture field / ScriptableObject shell). Wire-up = host the project's own parser classes in a .NET console harness with a minimal UnityEngine stub, repo parser files unmodified.
    • ⚠ FORMAT FINDING on the target file: pds3hx.fla (Frankie Foster rig, release frankie-rig-fla-v1, downloaded byte-exact 18,385,408 B) is NOT a ZIP/XFL .fla — file reports OLE2 "Composite Document File V2", i.e. the legacy binary FLA format (pre-CS5). The XFL parser cannot read it as-is; see the Frankie entry below for the decode path taken.
    • Pipeline role: read pro Flash rigs (layers, symbols, parts, tweens) so WG rigs can be built from their structure (USE-PRO-PRODUCTION-FILES-100% law).
    • VERDICT: WIRED+PROVEN — parser built from the project's own code (console host in tools/FlashXFLParser/harness/, .NET SDK 8.0.427) and proven on REAL rigs from cn-gigaleak-cartoon-vault release tv-gigaleak-fla-v1: Pim rig (5 part layers) and Charlie rig (18 symbols / 33 layers / 73 frames, 9-layer master symbol). The Frankie target file is a legacy pre-CS5 OLE binary (parser detects + reports it honestly); its structure was decoded at OLE level — 131 symbols, 466 named parts incl. the full 3/4-view set. Full detail: tools/FlashXFLParser/WIRING.md.

    • Upstream: https://github.com/synfig/synfig release v1.5.5 (pinned in cape-jones wiring doc)
    • Install: official AppImage SynfigStudio-1.5.5-2026.03.15-linux64-79bf7.appimage → ~/workspace/tools/synfig/ (was: EMPTY directory), extracted (no FUSE on this VM)

Extracted with a purpose-built Joliet-tree ISO reader + zisofs block decompression (11,383 files → extracted/); soname symlinks recreated from ELF SONAMEs (they live only in the Rock Ridge tree).
