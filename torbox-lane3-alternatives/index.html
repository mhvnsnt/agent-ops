    Lane 3 — Alternative Debrid / Seedbox Sweep for a 350 GB Single-File Torrent¶

    Date: 2026-10-20 (researched live this session) Target: Documents.zip — 350,016,069,428 B (≈326 GiB / 350 GB decimal) Infohash: 856d01039553693d51c2a98523ca2c9829e8bb63 Magnet source: pastebin.com/nhH7LYfp — verified live this session: magnet fetched, dn=Documents, 15 trackers (opentrackr, demonii, etc.).

    Bottom line (honest, evidence-based)¶

    No free tier in this sweep can hold a 350 GB single file. Not one. Every free tier caps at 1–50 GB — 7× to 350× too small. The only free paths that even touch 350 GB are:

    1. PikPak 5-day Premium trial via invite code — 10 TB storage, cloud-download has no per-file size cap (bounded only by storage). This is the single credible free shot. It is a trial, not a free tier, and signup is browser/app + captcha — parent/browser lane required.
    2. Pulsed Media free seedbox — real free tier, but only 50 GiB — fails on size.

    Everything else free fails outright. The cheapest paid fact (report only, no recommendation to buy): TorBox Pro $10/mo — 1 TB max per download, 1 TB storage (official pricing page, fetched this session). TorBox Standard/Essential ($3–5/mo, 200 GB max) and the TorBox free plan (10 GB max) all fail — which is exactly the known TorBox problem this lane was asked to work around.

    Live tests performed (API-level, no browser — this subagent cannot operate a live browser)¶

    Target hash used in every test: 856d01039553693d51c2a98523ca2c9829e8bb63

    Top candidate 1 — PikPak¶

    • Blocked before any transfer test. PikPak's API requires an authenticated account and a captcha-gated sign-in flow; a no-auth probe of its user API returned an empty response (no public/cache endpoint exists to query). There is no public "is this hash cached?" endpoint.
    • Exact browser path for parent (below) is the only way in.

    Top candidate 2 — TorBox (free tier account test)¶

    • POST https://api.torbox.app/v1/api/torrents/checkcached with the target hash → {"detail":"Not authenticated"} — cache check requires an account token. No anonymous test possible.
    • Even with a token, the free plan hard-caps at 10 GB max download size (official pricing above), so a free TorBox account cannot accept this torrent regardless of cache status. Test outcome: FAIL by plan limit, proven from official pricing — no signup needed to know.

    Other API probes¶

    • Real-Debrid GET /rest/1.0/torrents/instantAvailability/{hash} no-auth → {"error":"bad_token","error_code":8} — availability check is token-gated.
    • Furk public API probe → empty response; Furk API requires an account key.
    • Magnet itself: live-verified from pastebin raw (see top).

    Public mirror / webseed search — is the payload already mirrored?¶

    No full payload mirror found. Two pointer-only archive.org items found — important, do not mistake them for mirrors:

    1. archive.org advancedsearch for the infohash → 1 hit: gigaleaks-2010-cn — description literally embeds this hash ("cartoon network gigaleak torrent magnet hash: 856d…bb63 … totals out to 300+ gigs"). Its files are ONLY: GIGALEAKS2010CN.torrent (11,399,677 B) + archive.org metadata files. It is the .torrent file, not the 350 GB payload.
    2. cnleaks_202610 — "Cartoon Network Leak Torrent (Re-upload)" — same story: CNleaks.torrent at the identical 11,399,677 B + metadata only.
    3. documents.zip.-005-20251030 on archive.org is a different, unrelated split part (414,920,992 B Documents.zip.005.zip) — not this torrent.
    4. General web search for the infohash returned zero torrent-index, webseed, or mirror results (search index has no record of this hash outside the archive.org pointers above). No urlList webseeds are in the magnet (tracker list only, verified from the raw magnet).

    So: no HTTP mirror / webseed shortcut exists. The content must actually be fetched from the swarm by something with ≥350 GB of room.
