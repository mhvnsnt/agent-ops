    ANTI-CLOBBER LAW (owner 2026-10-17)¶

    The incident¶

    On 2026-10-17, commit cd3bf38 ("DXMMII limb system", branch feat/dxmmii-limb-system, merged via PR mhvnsnt/western-heart#221) deleted 54,456 files against 105 legitimate additions. The agent committed from a working tree that was missing tens of thousands of files; git add -A swept every missing file in as a deletion. The commit message said nothing about deletions. Nobody checked the deletion list before committing or merging.

    The 105 additions were the agent's real work (all under tools/limb-system/dxmmii/). Everything deleted was recovered from git history — but it should never have happened.

    How a tree gets gutted (any one of these is enough): - Working in a directory that isn't a complete clone (partial checkout, interrupted clone, or files removed to "save disk"). - A cleanup process, VM replacement, or another lane deleting files out from under the working tree. - The agent itself deleting directories it didn't think it needed.

    In every case the failure is the same: git add -A turns "files missing from my tree" into "files deleted from the repo", silently.

    The law¶

    1. Read your deletions before every commit. Run git status and git diff --cached --name-status. Every deleted file must be something your task meant to delete. If you see deletions you can't explain, STOP. Do not commit. Assume your environment is corrupted — do not try to "fix" it by committing.
    2. Never git add -A or git commit -a in a tree you didn't fully populate yourself. If you didn't clone it and watch it finish, verify the tree is complete first — compare file counts against the remote branch. A tree missing files turns every missing file into a deletion the second you stage everything.
    3. Say what you deleted, in the commit message. If you delete files, the message names the directories or file types and why. If the message says one thing and the diff shows 50,000 deletions, that's a hard failure — do not push it.
    4. Deletion circuit breaker. Any deletion outside your task's scope blocks the commit. "My task touches 10 files but the commit deletes 500" is never fine. Stop and report instead of committing.
    5. The merger checks the deletion list. Before merging any PR, read what it deletes and match it against the task. Deletions the task doesn't explain block the merge. A giant diff's deletions are never "probably fine."
